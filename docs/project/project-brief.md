项目8：面向存算分离向量检索的图索引访问轨迹分析与分级读取优化

一、项目背景

随着大模型、推荐系统、语义搜索和多模态应用的发展，文本、图像、音频等非结构化数据通常需要经过人工智能模型转换为高维向量。向量检索的任务，是从大规模向量集合中找出与查询向量最相似的数据对象。

由于逐一比较全部向量的计算开销较高，实际系统通常使用近似最近邻搜索技术。HNSW、Vamana等图式向量索引通过在相似向量之间建立连接，使查询能够沿图结构逐步接近目标区域，在查询速度和检索准确率之间取得较好的平衡。然而，图索引需要保存大量节点邻接关系，其存储开销会随着数据规模持续增长。

在推荐系统、知识库和实时数据分析等应用中，向量数据还会不断增加、删除或变化。图索引插入新节点时，需要搜索近邻并修改已有节点的邻接关系，因此更新操作会与查询竞争处理器、内存和I/O资源，可能造成查询吞吐下降和尾延迟升高。

为了支持更大规模的数据，可以采用存算分离架构，将查询计算与向量数据存储部署在不同节点。计算节点负责图搜索，存储节点负责保存图索引和向量数据。查询过程中，计算节点需要通过网络读取图节点的邻接信息，因此每次读取的数据量会直接影响网络开销和查询性能。

动态图索引通常为每个节点分配固定大小的图记录，以便快速计算地址，并为后续增加邻居预留空间。但是，不同节点的实际邻居数量并不相同。如果每次都读取完整记录，会传输大量未使用的预留空间；如果先读取记录头部，再根据邻居数量发起第二次精确读取，又会增加一次依赖性的网络访问。

针对这一问题，提出了将固定物理记录与可变传输粒度相分离的ClassExtent机制：将邻接表划分为若干数据块，根据节点的邻居数量选择一次读取的前缀长度，从而减少无效数据传输，同时避免每个节点都进行两次网络读取。

四、项目开展

1. 向量检索基线运行与基本概念学习：在SIFT100K等数据集上构建和查询HNSW索引

2. 图节点访问轨迹与邻居数量分析：统计图搜索过程中访问的节点的邻居数量分布

3. 实现一个基于访问轨迹的读取开销模拟器，比较以下三种策略。

策略一：固定完整读取

假设每个图记录最多能够保存固定数量的邻居。无论节点实际具有多少邻居，每次都读取完整记录。该策略只需要一次读取，但可能传输较多无效字节。

策略二：精确两阶段读取

第一次只读取节点头部，获得实际邻居数量；第二次读取精确长度的邻接表。

该策略传输的数据量较少，但每个节点需要两次具有依赖关系的读取。

策略三：分级前缀读取

将邻接表划分为若干固定粒度的数据块。例如，每8个邻居为一个读取级别。

4．参数实验与结果分析：至少选择三个分级粒度，例如每4个、8个和16个邻居为一级，研究粒度大小对结果的影响

5. 动态更新下的分级信息失效与修复
