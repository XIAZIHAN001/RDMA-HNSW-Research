## 研究背景

存算分离向量检索把计算与图索引存储部署在不同节点。HNSW 查询要反复获取节点向量和邻接表；为了地址可计算和预留更新空间，图记录按固定容量存储，但实际邻居数量往往小于容量。完整读取造成空槽传输，先读头部再精确读取则增加依赖往返。本课题研究固定物理记录与可变传输粒度的分离，以及动态更新后历史长度信息的检查与修复。

## 课题内容

1. 在 SIFT100K 等数据集上构建、查询 HNSW，理解近似检索、Recall、索引参数和读取路径。
2. 采集查询访问轨迹，统计实际访问的节点、图层、degree、容量及热点分布。
3. 实现轨迹读取开销模拟器，比较完整读取、精确两阶段读取和分级前缀读取。
4. 比较至少三种粒度（如 4、8、16），解释请求次数、有效字节、浪费字节和模型延迟之间的关系。
5. 验证插入、删除或更新造成的历史 degree 信息失效，检查低估补读、过估和缓存淘汰。

教师代码仓库的实验要求进一步区分三个 Baseline 与一种新机制：`fixed`、`header_actual`、`cached_length`、`prefix`，本工程按四种独立策略实现。具体研究要求也见[教师实验说明](../experiment.md)。

## 验收约束

- 使用统一数据、图结构、搜索参数和随机种子；改变读取策略时保持返回的完整邻居及其顺序。
- 缓存以节点 ID 和图层联合索引；通过本次读取的真实 degree 检查预测，不用 generation 预读代替低估修复。
- 模拟、本地 mmap 和真实 RDMA 分开记录；mmap 耗时和假设网络参数不能作为 RDMA 性能。
- 正确性核验使用对应快照的有效向量集合，单独记录核验开销；性能计时不能混入暴力检索。
- 保留配置、代码版本、原始日志和复现方式。正式矩阵覆盖规模、粒度、缓存容量、更新比例、并发度及随机/热点更新。

最低开发环境为 Ubuntu Linux 或 Windows WSL、4 核 CPU、16 GB 内存、约 20 GB 空间、Python 3、NumPy；高性能实现使用 C++20/CMake。GPU 不作为完成条件。真实 RDMA 验收需要计算端和存储端及相应设备、驱动和网络。
